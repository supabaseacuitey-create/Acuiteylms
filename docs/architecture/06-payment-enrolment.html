Architecture Diagram 06

Payment & Enrolment Flow Architecture

Unified enrolment pipeline routing free courses directly to enrol_self and paid enrolments through Moodle's core_payment API with server-side gateway-specific signature and payment-status verification for Razorpay & PhonePe.

Server-Side Secret Isolation
API secrets and webhook secret keys for Razorpay & PhonePe reside strictly in Moodle database configurations (mdl_config_plugins) on the Hostinger KVM. Client applications never receive secret tokens.
Gateway-Specific Verification
No enrolment record is committed upon frontend redirect alone. Enrolment occurs exclusively when the server executes gateway-specific signature/authenticity validation, order-amount checks, and payment-status verification.
Idempotent Webhooks & Retry
Payment callbacks check mdl_payments for duplicate transaction IDs before enroling, preventing double allocation while handling network dropouts or retry spikes gracefully.
